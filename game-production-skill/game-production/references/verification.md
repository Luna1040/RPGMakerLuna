# 验证、交接与发布

把检查分为四层，按改动范围执行：

1. 素材合同：RGBA、统一画布/原点、边缘无截断、时序合计、事件落于动作内、安全相对路径、记录源帧。存储 crop 重建后与原稿逐像素比较可见 RGB 与 alpha，完整元数据不变。
2. 机制：输入路由、伤害/无敌/冷却、目标去重、死亡、掉落拾取装备、队友独立 HP、存档往返、任务奖励幂等。
3. 真实场景：新区域 spawn→遇敌→按键技能→清场→传送门→boss→回城交任务。每种 NPC 对话商店至少测试一次；不能只测直接调用服务。
4. 可视验收：动画实际播放、首尾循环、深浅底残留、挥剑边界、转身、实际发弹点、受击框可视化、黑幕/区域标题、键盘选项、分辨率和 Web 焦点。

Godot 流程：先 `godot --headless --editor --path PROJECT --quit` 导入，再运行项目已有测试，最后可视运行。Godot 有时 SCRIPT ERROR 后仍退出 0，测试门槛同时读取错误日志与明确 PASS 标记。不要只靠进程退出码。

发布前锁定素材与代码版本再导出，避免每次晚修一行都重新上传巨大 pck/zip。包内提供一个正式入口、版本/校验和、操作说明和已知限制。Windows cmd 与 macOS shell 入口分开；GDScript 通常可共用，但测试各平台路径大小写、文件权限、Godot 版本和 Web 导出能力，不能把 Windows exe 当 Mac 入口。Git LFS 素材要求 clone 后拉取，不能把指针当 PNG。

测试截图目录加 `.gdignore`，排除生成缓存、模型权重、下载碎片、私有配置、令牌、个人存档。字体子集覆盖新增区域/NPC/装备文本。地图图片要存项目内，不引用生成器临时路径。

交接写明：正式工程/启动入口、生成参数与源文件、复核过的动作、测试报告、导出版本及已知缺陷。已有受击末帧淡出不叫死亡动画；静态立绘轻摆不叫职业闲置动画；“已提交生成”不叫“资产已完成”。
