# B-12｜完整生成战役运行时闭环实施说明

## 完成结果

B-12 已把 B-07～B-11 的 Agent 创作结果接入同一条可验证、可发布、可导入、可启动、可存档的 Godot 战役链路。生成结果不再停留在分析报告或世界蓝图预览，而是能作为独立新战役进入真实 `stage.tscn`。

完整闭环为：

`Main Agent 合并 → 严格草案校验 → 人工预览令牌 → 不可变发布 → 隔离安装 → 新会话启动 → 真实运行时消费 → 独立存档`。

## 已接通的生成元素

- 世界背景、区域图与初始城镇：`world-blueprint/1` 编译为 `world-bundle/1`，随战役内容一起签名和安装。
- NPC：定义、场景居民、肖像、环境台词与条件对话均由战役注册表加载。
- 主线/支线：任务、目标、前置条件、奖励和剧情图进入现有 Adventure 系统。
- 好感度：NPC 声望条件、选择效果与任务奖励进入存档状态。
- 道具：生命/法力消耗品可以由 Systems Agent 创建并成为任务奖励或商店商品。
- 装备：生成装备进入骑士装备目录，可购买、持有、穿戴并参与数值计算。
- 商店：生成库存经过材料价格、输出类型和引用完整性校验后进入交易界面。
- 地图旅行：运行时从生成地图的 `exits` 读取相邻区域，使用目标地图出生点完成场景切换。
- 独立存档：快照绑定战役内容上下文和动态地图 ID，不能跨战役误读。

## Main Agent / 子 Agent 协作变化

- World Agent 负责声明式世界蓝图，不生成脚本或资源路径。
- Narrative Agent 负责任务和对话草案。
- NPC Agent 负责 NPC 呈现与对应对话。
- Systems Agent 获得受限的新 ID 权限，可提交装备、道具和商店 `content_draft`，仍不能直接改运行时。
- Validator Agent 审查全部上游结果后，Main Agent 将内容操作与已编译世界合并成一个草案。

所有操作仍受 `allowed_targets`、作者角色、内容修订号、目录哈希、资源白名单、交叉引用和不可变发布校验约束。

## Godot 运行时改造

- `ContentRegistry` 在战役激活时同时加载世界、NPC、剧情、道具、装备和商店。
- `WorldRegistry` 支持动态区域集合、动态初始区域和生成地图契约，同时保留官方庭院/古塔回退。
- `stage.gd` 在新战役启动时直接载入生成初始地图。
- `GameRuntime` 的存档校验、传送和城镇判定不再写死 `town/ruins`。
- 冒险面板显示生成区域名称和相邻区域旅行入口。
- 退出自定义战役后会恢复官方内容、官方地图和官方存档目录，生成内容不会泄漏。

## 安全边界

- Agent 仍只能生成结构化数据，不能生成或执行 GDScript。
- 世界资产只接受 `asset.world.*` 白名单 ID；NPC 资产只接受注册 ID。
- 世界、内容、发布物、安装包分别带确定性 SHA-256 校验。
- 预览令牌与草案、候选内容、基础目录和修订号绑定，预览后修改会被拒绝。
- 自定义战役必须经新会话边界启动，不能热替换当前运行中的官方游戏。
