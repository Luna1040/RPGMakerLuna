本阶段解决的是“已发布、已安装的 Agent 生成战役如何安全进入真实游戏”。它不在当前场景热替换任务或 NPC，而是强制结束旧会话，通过空白 bootstrap 场景完成内容提交，再创建新的 `stage.tscn`。

## 实际启动链路

```text
网页工作台 / Main Agent
→ WorkbenchBridge.preview_campaign_launch(project_id, campaign_id)
→ Godot 复检已安装战役包并返回 launch_token、战役名、哈希、存档目录
→ 玩家确认“结束当前会话并开始新战役”
→ WorkbenchBridge.start_campaign_session(project_id, campaign_id, launch_token)
→ SceneTree 接受 bootstrap 场景替换
→ 清理 GameSession 临时跳转、待执行 Runtime Patch、旧 GameRuntime 引用
→ 旧 gameplay scene 退出
→ campaign_bootstrap.tscn 再次读取并验证 manifest.json + content.json
→ ContentRegistry 原子切换技能、装备、NPC、任务、对话与冒险目录
→ 新 stage.tscn 创建 GameRuntime
→ GameRuntime 绑定该战役自己的 SaveStore
```

返回官方庭院调用：

```gdscript
WorkbenchBridge.start_official_session()
```

它同样经过 bootstrap，不会在当前场景中直接替换目录。

## 工作台公开接口

### 1. 预览启动

```gdscript
var preview = WorkbenchBridge.preview_campaign_launch(project_id, campaign_id)
```

成功结果包含：

- `display_name`
- `launch_token`
- `manifest_hash`
- `content_hash`
- `save_directory`
- `activation_policy`
- `replaces_current_session: true`
- `activates_immediately: false`
- `requires_scene_bootstrap: true`
- `auto_loads_save: false`

预览不会修改当前注册表、当前场景或存档目录。网页应在此阶段显示确认框。

### 2. 确认并启动

```gdscript
var result = WorkbenchBridge.start_campaign_session(
    project_id,
    campaign_id,
    preview.launch_token
)
```

同一时刻只允许一个新会话转换。令牌不能跨项目或跨战役复用；战役包在预览后发生任何变化都会被拒绝。

### 3. 能力查询

`WorkbenchBridge.capabilities()` 新增：

- `campaign_session_activation: "scene_bootstrap_new_session_only"`
- `content_context`
- `active_save_directory`

网页可以据此判断当前是官方内容还是自定义战役，以及当前三槽存档实际属于哪个目录。

## 内容与存档隔离

官方存档仍使用：

```text
user://rpg_saves
```

生成战役使用：

```text
user://projects/<project_id>/campaigns/<campaign_id>/saves
```

每个新快照都写入 `content_context`：

```json
{
  "kind": "campaign",
  "project_id": "project.rpgmakerluna.courtyard",
  "campaign_id": "campaign.example",
  "content_hash": "...",
  "manifest_hash": "..."
}
```

加载时该对象必须与当前 `ContentRegistry` 完全一致。以下情况全部拒绝：

- 官方存档进入自定义战役；
- A 战役存档进入 B 战役；
- 同一战役 ID 的内容或 manifest 已变化；
- 自定义战役存档缺少 `content_context`。

为兼容旧版本，没有 `content_context` 的旧存档仅可在官方内容上下文读取。

## 失败保护

- bootstrap 资源无法加载或 SceneTree 拒绝切换时，当前场景和当前会话状态保持不变。
- 战役包在排队后被篡改时，bootstrap 提交失败并恢复官方内容与官方存档目录。
- 内容校验任一项失败时，不会留下半套自定义目录。
- 新战役启动不会自动加载、复制或覆盖任何存档槽。
- 场景切换前的待执行 Runtime Patch 不会跨进另一个战役。
- 生成代码、任意资源路径和任意文件路径仍不被接受。

## Godot 改动位置

- `systems/content/campaign_session_service.gd`：预览令牌、新会话调度、bootstrap 提交、失败回滚与存档目录状态。
- `systems/content/campaign_bootstrap.tscn`：无 gameplay 节点的内容切换边界。
- `systems/content/content_registry.gd`：完整战役目录原子激活与内容上下文。
- `systems/game_runtime.gd`：按战役创建 SaveStore，并在快照中写入/验证 `content_context`。
- `systems/workbench_bridge.gd`：向网页工作台暴露预览、启动、返回官方战役和能力查询。
- `tests/campaign_session_pipeline_test.gd`：真实执行两次 `stage ↔ bootstrap` 场景链路。
