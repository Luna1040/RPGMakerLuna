# 游戏内 Codex 助手（黑客松）

从工作区根目录双击 `运行游戏-AI开发版.cmd`，服务自动启动游戏。F1 或右侧按钮打开助手，Ctrl+Enter 发送，ESC/F1 返回游戏。打开时暂停并记录现场截图；发送时附带当前场景、区域、角色坐标。需求直接交给本机 Codex 修改整个项目。可以继续试玩，任务完成后自动导入检查并重启桥接器自己启动的游戏，恢复到正常开局，不保存现场。

本次实现采用 [官方 Codex app-server](https://learn.chatgpt.com/docs/app-server)，使用已有 CLI 登录与模型设置，不是控制 Codex 桌面聊天窗口，也不会继承这段对话全文。新的游戏开发会话保存在 `.game-assistant/thread.json`，服务重启后续用；生产流程从工作区文档与 game-production skill 读取。CLI 可用能力不保证与桌面内置工具完全相同；ComfyUI 可通过本地脚本调用，图像生成能力按执行端实际工具确定。

实现：Godot Autoload → 本机 HTTP 桥接（127.0.0.1:9320，临时 Bearer 凭据）→ Codex app-server 标准输入输出 → 修改/验证 → Godot 重启。仅 `--ai-dev` 启用面板，普通游戏入口不变。F8 原慢动作保留。节点与命令进度、文件修改事件和最终回复都在面板里。

已允许项目内编辑和重启，使用 workspace-write / never，不启用 unrestricted/danger-full-access。超出执行端权限的操作会报告限制；不会自动批准额外权限请求。一次处理一个需求；需停止时点“停止任务”，等待结束再发下一条。不要同时在另一个会话修改同一功能。

依赖：本机 `codex` 命令已登录、`.tools/node-v22.17.0-win-x64/node.exe`、`.tools/godot/Godot_v4.7.2-stable_win64.exe`。桥接器支持 CODEX_BIN / GODOT_BIN 环境变量覆盖；当前一键启动脚本是 Windows 版本。截图、请求记录、连接凭据、导入/运行日志都在 `.game-assistant/`，不应提交 Git。

导入失败时保留当前游戏并报错；该检查能发现脚本解析/导入错误，不保证玩法正确。让助手按改动运行对应测试，再在游戏里复测。面板里的“立即重启游戏”会丢失本次未保存的游戏状态，正是本黑客松的预期行为。

验证命令：`godot --headless --path godot-belt-map --script res://tests/game_assistant_test.gd -- --ai-dev`。该测试需桥接器已经写出本机 connection.json；可视模式额外保存面板截图。
