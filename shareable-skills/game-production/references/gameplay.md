# Godot 制作与踩坑

## 先定义合同

分开角色状态/数值、技能定义、AI 决策、动作表现、场景数据和存档。角色至少有 HP、阵营、职业技能、冷却、受击/死亡；队友不是贴在主角旁边的动画，要有独立目标、HP、支援技能、跟随/驻守/待命和倒下恢复。城镇 NPC 的职业闲置和战斗角色的 stand/walk/attack/hurt 分别验收。

资源合同建议：顶层 id/version/canvas/portrait，动作下 frames[{file,source_frame,duration_ms}]、duration_ms、pivot、scale、event_ms、review_status。脚底 pivot 全动作帧固定；存储裁切用动作联合 bbox 和四周 4px 留白，记录 storage_crop；用 AtlasTexture margin 恢复原画布，不能修改事件与原点。

机制包括明确伤害窗口、一次攻击对目标去重、受击中断、击飞与落地、浮空高度、感电持续伤害、死亡退出 AI。武器长度变化和缺失需查源帧，不靠加大 hitbox 遮掩。范围可在视觉剑锋基础上给少量容错，与敌人的受击框相交，而不是只测目标中心。投射物由代码计算位置和碰撞，拖尾沿实际飞行方向。

## 地图与副本

区域注册表定义安全城镇/战斗区域、出生点、可走范围、传送门目标和门槛。不要到处写 `zone == town`，否则新城镇商店不能用。小地图由当前区域数据生成，避免旧庭院道路出现在林道。

房间图使用 room_id、邻接边、门、刷怪组、清场状态、关底 boss。演示可先线性三房间，但不要宣称已有完整分支迷宫。清场后给明确前进门、奖励或返回指引；普通玩家无需进入开发菜单刷新敌人。新一波与房间一致，防止在旧房间刷出下一房间。

换图遮罩置于持久 Autoload 的高 CanvasLayer，先淡到黑并渲染一帧，再加载/切场景，ready 后淡入并居中显示区域名称。失败时恢复可操作状态；不要切场景先卡住再画黑幕。

## AI 曾发生的真实问题

- 新副本仍用旧竞技场的范围/出生距离，敌人无法接近玩家。测试每张地图的实际出生和可走区域。
- 角色与敌人 X 接近、纵深不同，左右切换间距导致抽搐：先修正纵深、加入朝向死区与目标迟滞，分离移动方向与攻击朝向。
- 群体分离力使返程永远到不了出生点：返程时限制或关闭分离力，最后一步不越过目标。
- 技能击中服务单测通过但真实按键无交互：必须覆盖按键→状态→动作事件→命中→HP/反应整链。

## 键盘界面与输入

本实例默认方向键移动，X 普攻、C 跳、Z 上挑、Q/W/R 技能，双击方向 0.5 秒内奔跑。它们是项目默认，不强制覆盖其他游戏设计或用户改键。

对话先于游戏消费按键：方向键移动高亮、空格确认一条/选项、ESC 关闭弹层。忽略 key echo，避免长按一口气跳完整段。检查拥有焦点的按钮是否吞 ESC、是否误触发游戏攻击。改键迁移只修正旧默认，保留自定义；逻辑 action ID 不必跟物理键同名。

背包 hover 显示装备数据对比、人物数值面板；拾取、装备、掉落都走同一数据服务。NPC、道具需要合理地面碰撞，不止美术形状。

## 网状任务

节点记录状态与前置条件组合，边表达解锁、互斥、替代路径及结果；事件驱动推进，奖励幂等。剧情选择改变标记/声望再影响后续节点。存档保留选择和任务状态并带版本迁移；从 NPC 注册表补充新默认，避免加载旧档后键缺失。检验两条不同路径、放弃/重接、重复领取和重载存档。不要以一串线性任务冒充网状叙事。

## 开发工具

提供可切换碰撞/攻击范围/受击框、AI 目标/状态、房间/传送门、加入队友/模式/恢复、重置测试目标。标注开发模式，正式试玩入口只留一个；快捷键避开浏览器占用键，支持点击等价操作。
