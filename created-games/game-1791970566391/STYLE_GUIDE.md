# 《昨夜不存在》Demo 美术与镜头约束

本文件补充 `GAME_DESIGN.md` 第 12、17、18 节。用户要求原创赛博朋克像素风格；参考图只用于氛围和构图分析，不得直接当作游戏素材、描摹具体场景，或复用其中的文字、人物和品牌。

## 三张参考图的用途

- `design-references/03-pixel-interior.png`：最高优先级。参考可见的像素颗粒、硬边轮廓、小道具密度和室内局部光照；酒吧要温暖、老旧、有生活痕迹。
- `design-references/01-street-depth.png`：参考街区的前中后景层次、雨夜地面反光、局部霓虹与可穿行空间；将这些语言重新设计成 320×180 的像素场景。图中文字、广告、角色、具体布局不复制。
- `design-references/02-city-atmosphere.png`：只参考城市尺度、远景雾和冷色纵深，不参考其写实渲染、人物或具体建筑。

## 技术与表现规格

- 俯视 2D 战斗与可步行酒吧，营造 2.5D 观感：按脚底 Y 坐标排序；建筑、吧台、灯箱等前景可遮挡角色；角色脚下有清晰阴影；远景/高层背景可有轻微视差，但交互与碰撞仍在 2D 平面。
- 内部画布 320×180，默认显示 1280×720，整数 4 倍放大、Nearest 过滤。地图以 16×16 网格组织，大型道具用 32×32 模块。避免平滑缩放、任意尺寸图像贴屏和亚像素抖动。
- 开场酒吧世界为 768×432，当前以 5/12 Nearest 映射到 320×180，左卡座、中央吧台和右舞池完整同屏。酒吧相机固定，不再追随人物裁掉大片区域；UI、对话与提示仍按 320×180 屏幕尺寸绘制。
- 角色轮廓、攻击前摇、弹道、交互提示始终清晰。霓虹仅用于局部叙事和导视；不要用强辉光淹没像素形状。酒吧是炭黑、酒红与暖琥珀；记忆空间以安保区青紫、医疗室冷青绿、根层洋红与破碎感区分。
- 已有偏写实的记忆地图生成图片不作为正式素材，不要重新接入。2026-10-15 用户明确授权通过团队远程服务制作标题封面、开场酒吧背景，以及主角酒保和周骁的角色小样。本轮战斗资源先以原创程序像素图制作可玩 Demo 候选；正式角色、动作和地图仍需用户在真实游戏画面确认后再扩展。
- 酒吧底图采用鲜明青紫、暖琥珀与硬边像素质感；禁止灰暗脏糊、写实材质和大面积辉光。远程图负责室内静态底层，雨窗灯光采用整数像素视差；吧台前脸从同一画作提取为独立透明前景贴图并按脚底 Y 排序，保留器具与吧台原有细节。人物脚下阴影、通讯器与设施升级反馈由 Godot 独立绘制，不能依赖单张烘焙图完成遮挡。
- 酒吧内不出现潜航机器或地下终端。调酒器具区是主要交互锚点，精确悬停文案为“开始调制”；结算、设施升级和结尾入口统一由普通吧台通讯器与灯带反馈承担。
- 调酒器具只允许形成占台面约 10–15% 的单一小簇，鼠标热点紧贴器具，不得用整片吧台矩形代替。中央吧台前脸必须保留至少 32px 的员工缺口，底图、前景 alpha 和碰撞使用同一开口；角色可从入口实际走入吧台内侧。
- 酒吧两名角色统一使用 80×80 RGBA 世界画布、脚底 pivot `(40,72)` 和独立阴影；全景映射后约占 27 屏幕像素。主角为蓝绿色长发的成年女性酒保，周骁为灰鬓、胡茬、宽肩的中年安保人员。各有 H3 正向走路和交互动作候选；这些 H3 帧只用于酒吧，尚未作为本轮战斗动作接入。转向、职业待机和正式视觉验收仍需后续制作。
- 周骁开场从画面下方入口外走入，经左侧通道到卡座；抵达前不可隔空触发对话。调酒页使用原创硬边像素酒瓶、摇酒器和透明调酒杯，青、红、薄荷、琥珀、紫作为品种导视色，属性与品质始终用文字说明。
- 舞池保留完整可踏入面积和至少两个不被家具占用的 NPC 对话站位；本轮只接入音乐设备调查与慢速整数像素灯光。灯光不可成为碰撞、不可持续闪烁，也不可压过交互文字。

## 战斗 Demo 的本轮美术合同

- `assets/combat/maps/` 中有三张彼此独立的 320×180 硬边像素底图：安保检查区的左右双出口、闸机和监控屏；医疗室的治疗床、扫描台和药柜；根层神经实验室的环形核心与洋红电路。底图只承载静态环境，门可用状态、碰撞、人物脚底 Y-sort、前景遮挡和攻击预警由 Godot 独立处理。食堂门可见但显示试玩版未开放，医疗室门在第一层清场并借身后可进入。
- 第一层敌方安保队长与普通安保均为近战。队长借身前的 `captain_melee` 小图和立绘保留同一制服、枪收在腰侧、手持电棍；借身后玩家才使用 `captain` 的持枪形态。女主保持蓝绿色长发、酒红马甲和电棍。第二层医疗员给予一次强化刷新机会，不借身；第三层校正者的攻击面积与光效可以震撼，但预警必须比特效更清楚，演示伤害保持低上限。
- 本轮资源按五种人物身份、六张透明立绘（队长借身前/后各一张）和 35 张 80×80 RGBA 战斗帧组织；所有战斗帧固定脚底 pivot `(40,72)`，在 320×180 画面中统一以 `0.5` 倍 Nearest 绘制，人物可见高度约 35 像素，普通 alpha 合成。女主、通用安保、队长两种持械形态和医疗员各有两相步行与关键攻击/受击姿势，校正者保持悬浮待机和攻击姿势。特效独立绘制，不把整个人物设为加法混合。
- 72×88 立绘在战斗 HUD 中会缩为小头像，须在真实窗口检查蓝绿发、安保帽/肩章、医疗口罩与校正者面罩是否仍可辨；若细节丢失，应离线制作专用小头像，不依赖运行时任意缩放掩饰。
- 具体文件、程序绘制脚本、尺寸/alpha/SHA-256 与对照图在 `assets/combat/README.md` 和 `assets/combat/manifest.json`。这些图是试玩候选，不是 H3 战斗动画或已确认的正式美术；Godot 实际渲染器静帧已用于复核角色比例、出口标识与三招特效，但不能替代连续操作时的步态、遮挡和 Boss 战手感验收。

## 制作顺序

先按 `GAME_DESIGN.md` 的 P0 完成从标题到结尾的完整可玩状态流，再逐项检查机制和视觉。实现进度要如实区分“代码完成”“能运行”“走通全流程”“美术已确认”，不要将占位美术或静态场景称作正式 Demo 完成。
